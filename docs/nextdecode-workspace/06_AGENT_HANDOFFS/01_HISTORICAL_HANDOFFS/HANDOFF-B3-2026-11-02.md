## 3. B3 final specification — requirements R1–R6

**Specification:** `ND_GOV_005_B3_REMEDIATION_SPEC_FINAL_2026-10-31.md`  
**Author/date/status in source:** Qoder, 31 October 2026, read-only specification. OpenCode is the sole implementation owner.

### R1 — Reuse-rights status parsing

- For a dict, read `status`, apply the specified fallback, trim whitespace, and lowercase.
- For a string, trim whitespace and lowercase.
- Other types produce an empty status.
- Accept exactly `permitted` as the local B3 compatibility basis.
- Empty/missing values and all other statuses fail closed.
- Do not broaden the accepted vocabulary.

### R2 — Cutout collection and card shape

- A persisted list is treated as the list of cards.
- An in-memory dict keyed by scene index is treated as its values.
- Other collection types are malformed.
- Every card must be a dict; malformed cards fail closed.
- Missing `claim_id` or `scene_index` affects labeling only, not the core rights decision.

### R3 — Missing cutout evidence

- An absent `cutouts` key is treated like an empty list for the zero-cutout branch.
- It is not a silent pass: the R5 selection proof is required.

### R4 — Non-empty cutout proof

For non-empty cards, require a dict `rights_gate` with:
- integer `checked` exactly equal to the number of cards; and
- integer `blocked` equal to zero.

Reject booleans where integers are required. Missing/non-dict gate or contradictory counts fail closed.

### R5 — Zero-cutout selection proof

For zero cards or absent `cutouts`, accept only when `evidence.cutout_selection` is a dict containing:
- a non-empty string `reason`; and
- an integer `budget`.

The specification requires an integer budget; do not silently add extra constraints unless separately authorized. `rights_gate.publish_ready` must not be used to approve the zero-cutout case. The module documentation should state this.

### R6 — Pipeline persistence

Persist `cutout_selection` in the pipeline evidence block:

`"cutout_selection": render.get("evidence", {}).get("cutout_selection", {})`

The specification says the renderer already emits the relevant keys; this is a persistence change, not authorization to redesign renderer or rights-gate computation.

### Error behavior and scope

Rights violations must raise `PublishNotAuthorized` with `code="blocked_rights"`, include the first finding in the reason, total violation count, and a violations list capped at 20.

Out of scope:
- Global rights policy changes.
- Asset licensing rules in `visual_quality`.
- Recomputing `cutouts.rights_gate`.
- Storyboard reason logic.
- Mapping local `permitted` into a CF-20 state.
